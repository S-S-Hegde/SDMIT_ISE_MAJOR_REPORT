\chapter{Introduction}
\section{Background}
The current technical recruitment and academic evaluation still face the monumental challenge of fair, accurate and secure evaluation of the candidates. The conventional recruitment systems use resumes, GitHub repositories, online certifications and portfolio websites to assess the candidates. However, traditional hiring platforms can be vulnerable to issues such as fake resumes, overstated skills, and duplicate or purchased code repositories. Recruiters often have to spend a significant amount of time manually checking GitHub activity, reviewing code authorship, and verifying whether the projects listed by an applicant were actually created by them. This makes the hiring process slower, more difficult, and less reliable.

In addition, the emergence of state-of-the-art Large Language Models (LLMs) and zero-cost generative AI tools has endangered traditional online assessments. Candidates can copy questions to other browser tabs, use generative bots to search for solutions or just memorise questions from publicly leaked question banks. Conventional Computerised Adaptive Testing (CAT) with Item Response Theory (IRT) solves some of these issues but has traditionally been based on pre-calibrated banks of tens of thousands of questions field tested with static difficulty indices. Such approaches do not work in the fast moving software development ecosystem where modern frameworks, languages and runtime paradigms change continuously.

VeriProof is designed, architected and built as a complete full-stack candidate proof-of-skill and anti-fraud verification ecosystem. It combines automated GitHub repository scanning, AST-level code claim auditing, Cross-Source Evidence Fusion, a novel 3-pass LLM bias-elimination question quality pipeline, a 2-part split adaptive test engine with strict Purgatory timeboxing, real-time client-side behavioral proctoring telemetry, and an interactive Dynamic Skill Tree. VeriProof is built on a hybrid MERN stack (MongoDB, Express.js, React.js, Node.js) application integrated with a dedicated Python FastAPI analytical intelligence microservice (\texttt{python\_engine}) and Google Gemini Flash inference, offering an auditable, transparent and meritocratic technical hiring paradigm.

\section{Problem Statement}
Existing recruitment platforms suffer from three severe, interrelated failure modes:
\begin{enumerate}
    \item \textbf{Unverifiable Portfolios \& Code Claim Fraud}: Candidates frequently claim deep full-stack or systems experience based on cloned open-source projects or template repositories without genuine code comprehension.
    \item \textbf{Vulnerability to Generative AI Assistance}: Traditional online exams rely on static, purely conceptual multiple-choice items (e.g., definitions, syntax lookups). In unsupervised environments, candidates query search engines and LLMs during testing, inflating scores without possessing practical troubleshooting competence.
    \item \textbf{Lack of Nuanced Forensic Telemetry}: Current proctoring solutions rely on crude binary disqualification triggers (e.g., webcam disconnects) rather than nuanced multi-parametric signals such as deceptive trap question responses, confidence calibration divergence, and response time distributions.
\end{enumerate}

\section{Objectives}
Key objectives of the VeriProof platform are:
\begin{enumerate}
    \item Build an automated pipeline to consume unstructured Job Descriptions (JDs) and parse role seniority, requisite skill domains and generate balanced calibration question pools.
    \item To implement a two-stage adaptive testing architecture: Phase 1 (50\% standardized calibration); Phase 2 (50\% dynamically personalized scenario-based debugging and architecture questions).
    \item To build a secure Purgatory Intermission system that strongly enforces recruiter-configurable timeboxing (5--15 minutes) to prevent candidate collusion while asynchronously computing the candidate's multi-dimensional Skill DNA.
    \item Build a 3-pass Question Quality Pipeline that removes LLM biases: length imbalance, hedging words, jargon imbalance, and absurd distractors.
    \item To embed proactive forensic counter-measures, including deceptive trap questions and confidence calibration prompts to compute an aggregate Forensic Trust Score ($0$--$100\%$).
    \item To offer interactive candidate dashboards with gamified Dynamic Skill Trees and recruiter consoles with percentile rankings and forensic audit trails.
\end{enumerate}

\section{Scope of the Project}
The primary scope of the VeriProof platform is to provide an automated, multi-tiered, fraud-resistant technical candidate evaluation environment that reconciles self-reported qualifications with verifiable computational evidence. The scope includes full-stack software development, RESTful API design, database schema architecture, asynchronous worker pipelines, LLM prompt engineering with strict JSON schema enforcement, client-side event proctoring telemetry, and cloud deployment. The system uses Role-Based Access Control (RBAC) for three different user personas, namely: Candidates (Students), Recruiters (Investigators) and System Administrators. The operational boundaries and deliverables of this system comprise:
\begin{enumerate}
    \item \textbf{Dynamic Job Description Competency Ingestion}: Ingesting arbitrary recruiter job descriptions via Google Gemini inference to dynamically extract normalized Capability Nodes and Competency Trees with relative weighting ($\sum W_i = 100.0$), eliminating dependence on static assessment templates.
    \item \textbf{Empirical Artifact and Codebase Forensics}: Validating candidate identity and repository claims against live GitHub commit histories, enforcing an author attribution threshold ($\ge 30\%$), detecting bulk-import anomalies ($\Delta t < 600\text{ s}$), and classifying starter scaffolding to prevent template cloning.
    \item \textbf{Cross-Source Evidence Fusion}: Reconciling resume claims against repository code artifacts using automated contradiction detection to penalize metric exaggeration, unsubstantiated assertions, and code plagiarism.
    \item \textbf{Two-Phase Computerized Adaptive Testing (CAT)}: Administering a calibration test (Phase 1) focused on core computer science foundations, followed by an enforced Purgatory holding state (5--15 minutes) that dynamically generates AST-grounded scenario debugging challenges (Phase 2) tailored to the candidate's verified codebase diffs.
    \item \textbf{Behavioral Telemetry and Lightweight Surveillance}: Auditing exam integrity through in-browser behavioral telemetry (tab switching frequency, focus-loss tracking, and response-time distribution) paired with deceptive trap questions, completely eliminating the need for invasive computer vision video streaming.
    \item \textbf{Multi-Dimensional Candidate Synthesis and Decision Policies}: Calculating deterministic trust scores, behavioral STAR metrics, and candidate percentile rankings configured across customizable hiring policies (\textit{Startup}, \textit{Enterprise}, \textit{Intern}, and \textit{Senior Technical Track}).
\end{enumerate}

\section{Methodology}
The VeriProof platform is architected around a decoupled multi-tier hybrid polyglot microservice framework that separates high-concurrency client session management from compute-intensive analytical intelligence and evidence reasoning. The methodological execution proceeds across four synchronized tiers:

\begin{enumerate}
    \item \textbf{Presentation Tier (React Frontend)}:
    Single-page application based on React 18, Vite, Tailwind CSS, Lucide-React, and Framer Motion, providing separate, highly reactive portals for candidates (examination console, skill tree, and portfolio review) and technical recruiters (Job Description manager and Investigator Hub).

    \item \textbf{Application \& API Gateway Tier (Node.js/Express)}:
    Manages user authentication (salted bcrypt password hashing and JWT lifecycle), resume intelligence routing, GitHub sync, adaptive question assembly, candidate exam state machines, telemetric event buffering, and Keep-Alive container watchdogs.

    \item \textbf{Analytical Intelligence Microservice Tier (Python FastAPI Engine)}:
    A dedicated Python 3.11+ analytical service (\texttt{python\_engine}) operates asynchronously to execute deterministic scoring models and cross-source evidence verification without blocking the main event loop:
    \begin{itemize}
        \item \textbf{Resume \& Repository Intelligence}: Uses PyPDF binary stream extraction and GitHub REST/GraphQL interrogation to build cryptographic evidence maps.
        \item \textbf{Evidence Fusion Engine}: Automatically cross-references claimed resume skills against extracted AST constructs, identifying contradictions (such as claims lacking codebase corroboration or inflated impact metrics).
        \item \textbf{Multi-Factor Capability Scoring}: Computes dimensional capability scores based on coverage, architectural depth, code complexity, reliability, and delivery consistency.
        \item \textbf{Trust Score Calculator}: Synthesizes technical performance, behavioral assessments, and categorical fraud deductions (fork penalties, plagiarism flags, and missing sources) into a normalized index $S_{trust} \in [0, 100]$.
        \item \textbf{Recruiter Decision Engine}: Evaluates composite candidate profiles against selected organizational policies to generate reproducible hiring recommendations (\textit{Strong Hire}, \textit{Hire}, \textit{Borderline}, \textit{Hold}, \textit{Reject}).
    \end{itemize}

    \item \textbf{AI Inference \& Data Persistence Tier}:
    Multi-provider generative AI pipeline powered by Google Gemini Flash (\texttt{gemini-2.5-flash} and \texttt{gemini-3.5-flash}) enforced via a strict 3-pass distractor validation pipeline, backed by a MongoDB Atlas clustered NoSQL datastore managing document schemas for users, parsed resume claims, repositories, dynamic skill progression nodes, and examination audit logs.
\end{enumerate}

\section{Introduction}
The advances in talent acquisition automation, candidate assessment based on scientific evidence, and anti-fraud profile verification have stimulated extensive academic studies. Today's recruitment environments increasingly need dependable solutions for verification of claims made by applicants, assessment of their actual programming skills, and prevention of fraudulent profile representation. This chapter represents an overview of relevant and up-to-date scientific literature on such topics as digital portfolios, GitHub analytics, recruitment fraud detection, and cloud-based evaluation platforms.

\section{Review of Existing Work}
Marinin et al. \cite{Marinin2025} introduced an electronic portfolio maintenance system to manage the learners' achievements and competencies. The paper states electronic portfolio adoption helps better skill showcasing, access, and professional visibility to recruiters and educationists.

Lebopa et al. \cite{Lebopa2025} offered information verification systems to avoid fraud qualification during the recruitment process. MULTI-LAYERED\_PERCEPTRON-based ANN implements Random Forest algorithm to increase accuracy in recruitment.

Thandar et al. \cite{Thandar2025} introduced MERN recruitment system includes client and server, deployed in Google cloud services ensure secure authentication. JWT verified each user from the recruiter to the candidates and admin. Feature include role-based Authentication System, Centralized Recruitment Management.

It supports resume screening and analyzes candidates' profiles for recommendation. Moreover automated the recruiters hiring workflow. 

Adawiah et al. \cite{Adawiah2024} explored transparency in e-recruitment system builds up Candidate's trust. Highlight communication as the key recruitment workflow for recruiters to maintain their image's transparency.

Agazzi et al. \cite{Agazzi2020} presented a Usability Study of LinkedIn Professional Digital Networking Platform. This survey helps understand how a digital platform affects both recruiter and job seekers.

Ajayi et al. \cite{Ajayi2024} have examined creative recruitment methods in the IT industry. The paper highlights various methods of recruitment including AI-based recruitment, data analysis, hackathons, coding contests, and automated resume screening methods.

\section{Comparative Analysis of Existing Methods}

\section{Identified Gap and Project Motivation}
Whereas existing literature discusses a variety of solutions for individual recruitment issues including resume parsing, credential audit, simple portfolio display, and natural language screening, none of the current systems has addressed the problems together. Traditional systems do not incorporate any unified approach that can help integrate source code validation at the level of repositories with fraud-proof skill evaluation. In addition, traditional testing systems are susceptible to generative AI tools as well as unauthorized browsing during the intermission period. The motivation for developing the VeriProof platform lies precisely in these issues.

\section{Summary}
The studies reviewed above reveal the essential requirement in the field of employing evidence-based candidate assessment. VeriProof is an initiative designed to address the deficiencies identified above and consists of the latest advances in web development technologies and artificial intelligence combined with code analysis and multi-parameter forensic telemetry. In sum, the prior art focuses on post-hoc credentials checking, isolated resume mining, or repository displaying with no live problem-solving validation. Through the use of proctoring, deceptive trap question telemetry, and two-level assessment process, VeriProof helps eliminate the gap between self-proclaimed candidate profile and his/her software engineering skills.

In addition to this, the framework will ensure that the system is resilient to any kind of unauthorized generative help by using time-boxing during the intermission phase in addition to code-based challenges. Through the generation of an integrity score of the candidates through their actions, an objective and immutable record of technical expertise is provided.

\chapter{System Analysis and Requirements}

\section{Existing System}
Current technical recruitment pipelines rely heavily on passive resume screening, self-reported skills on professional networking platforms, and static multiple-choice questionnaires administered via legacy Applicant Tracking Systems (ATS). In traditional setups, recruiters receive unverified PDF resumes and manually verify candidate credibility by browsing public GitHub profiles and conducting preliminary telephonic screens. Standard pre-employment technical assessments deliver uniform, predictable question banks across all test-takers, relying on static scoring thresholds and basic proctoring mechanisms such as intermittent webcam snapshots or window-blur detection.

\section{Limitations of Existing System}
\begin{enumerate}
    \item \textbf{Vulnerability to Codebase Impersonation and Clones}: Candidates frequently claim software engineering expertise based on cloned, purchased, or template-generated repositories without possessing deep architectural comprehension of the underlying codebase.
    \item \textbf{Assessment Degradation via Generative AI Exploitation}: Conventional multiple-choice exams rely on static conceptual questions. In unsupervised environments, candidates bypass evaluation by querying Large Language Models (LLMs) on secondary displays or copying prompts, inflating scores without demonstrating troubleshooting competence.
    \item \textbf{Excessive Recruiter Overhead}: Recruiters spend hundreds of manual hours vetting exaggerated resumes and conducting exploratory phone screens on candidates whose empirical abilities diverge sharply from their self-reported claims.
    \item \textbf{Binary Scoring Without Behavioral Telemetry}: Legacy testing platforms output primitive pass/fail percentages, completely ignoring granular problem-solving speed, tab-switching telemetry, and confidence calibration divergence.
\end{enumerate}

\section{Proposed System}
VeriProof establishes a verifiable, evidence-driven proof-of-skill evaluation paradigm that replaces unverifiable resume assertions with empirical code forensics and two-stage computerized adaptive testing:
\begin{itemize}
    \item \textbf{Dynamic Job Description (JD) Domain Parsing}: Ingests unstructured recruiter job descriptions via Google Gemini to extract role seniority, required competency domains, and project context constraints on the fly.
    \item \textbf{Automated Identity and Resume Claim Verification}: Cross-verifies resume text against user credentials to detect identity mismatches, vectorizing claimed competencies into structured cryptographic audit tokens.
    \item \textbf{GitHub Commit and AST Authenticity Forensics}: Interrogates commit logs (author email, frequency, and time deltas $\Delta t < 600\text{ s}$) to flag cloned repositories and tutorial dumps, using Abstract Syntax Tree (AST) contribution analysis to prove actual code authorship.
    \item \textbf{Two-Stage Computerized Adaptive Testing (CAT)}: Implements a 50/50 split architecture comprising a standardized Phase 1 calibration round, an enforced countdown Purgatory Intermission, and a dynamically assembled Phase 2 scenario debugging round.
    \item \textbf{Three-Pass Question Quality Pipeline}: Enforces deterministic algorithmic gates to eliminate option length variance, jargon imbalance, hedging language, and absurd distractors.
    \item \textbf{Multi-Parametric Forensic Trust Scoring}: Synthesizes hardware webcam monitoring, keystroke dynamics, tab switches, and deceptive trap question responses into an objective composite trust score ($0$--$100\%$).
    \item \textbf{Interactive Dynamic Skill Tree}: Generates a Directed Acyclic Graph (DAG) visualizing verified skill milestones, experience points (XP), and recruiter dossiers.
\end{itemize}

\section{Functional Requirements}
The VeriProof platform implements the following core functional requirements across its hybrid MERN and Python FastAPI intelligence backend:
\begin{enumerate}
    \item \textbf{FR-01 (Authentication \& Access Control)}: Safe user signup process, password hashing by bcrypt, role-based access control (Candidate, Recruiter, Admin), and JWT-based sessions.
    \item \textbf{FR-02 (Dynamic Job Description Competency Ingestion)}: The system must ingest arbitrary recruiter job descriptions, parsing them via Google Gemini inference to extract normalized Capability Nodes and Competency Trees with relative weighting ($\sum W_i = 100.0$).
    \item \textbf{FR-03 (Cryptographic Resume \& Artifact Extraction)}: The platform must extract candidate profile claims, education, and project links from uploaded PDF documents using PyPDF stream parsing.
    \item \textbf{FR-04 (GitHub Repository Forensic Interrogation)}: The system must connect to GitHub REST/GraphQL APIs, verify commit author email matching, enforce a minimum commit authorship threshold ($\ge 30\%$), and detect bulk-import anomalies ($\Delta t < 600\text{ s}$).
    \item \textbf{FR-05 (Cross-Source Evidence Fusion \& Contradiction Detection)}: The evidence fusion engine must automatically cross-reference candidate resume claims against GitHub repository AST evidence, identifying and flagging metric exaggerations and unsupported skill assertions.
    \item \textbf{FR-06 (Two-Phase Computerized Adaptive Testing \& Purgatory Control)}: The platform must administer a Phase 1 calibration test (50\% baseline), enforce a strict Purgatory intermission countdown timer (5--15 minutes), compute candidate Skill DNA (domain accuracy, response speed, and Foundational/Intermediate/Advanced tier), and deliver a Phase 2 100\% scenario debugging assessment.
    \item \textbf{FR-07 (Question Quality Bias Elimination)}: The system must execute a 3-pass LLM question generation pipeline enforcing distractor length ratios ($R_{len} \le 0.15$) and tech jargon parity ($R_{jargon} \in [0.70, 1.30]$).
    \item \textbf{FR-08 (Behavioral STAR Assessment \& Trap Telemetry)}: The system must evaluate candidate behavioral submissions using structured Situation, Task, Action, Result (STAR) metrics, while embedding misleading seed-bank trap questions and multi-level confidence prompts during technical testing.
    \item \textbf{FR-09 (Multi-Factor Forensic Trust Computation)}: The system must calculate a normalized Forensic Trust Score ($S_{trust} \in [0, 100]$) incorporating tab-switching telemetry, trap question performance, confidence calibration, and explicit fraud penalties.
    \item \textbf{FR-10 (Dynamic Skill Tree \& Policy-Driven Recruiter Ranking)}: The system must visualize unlocked candidate skill nodes via an interactive DAG and evaluate candidate capability vectors against customizable organizational hiring policies (\textit{Startup}, \textit{Enterprise}, \textit{Intern}, \textit{Senior}) to generate leaderboards, percentiles, and verifiable recommendations.
\end{enumerate}

\end{itemize}

\section{Proposed Methodology / Algorithm}
The candidate Skill DNA classification algorithm computes empirical proficiency vectors across all evaluated technical domains:

\begin{equation}
\text{Accuracy}_k = \frac{\sum_{i=1}^{N_k} C_{k,i}}{N_k} , \quad C_{k,i} \in \{0, 1\}
\end{equation}

\begin{equation}
\bar{T}_k = \frac{1}{N_k} \sum_{i=1}^{N_k} T_{k,i}
\end{equation}

where $C_{k,i}$ is the correctness of question $i$ in skill domain $k$, $T_{k,i}$ is response duration in milliseconds, and $N_k$ is total questions in domain $k$.

The candidate is assigned to a competency tier per domain:

\begin{equation}
\text{Tier}_k = \begin{cases} 
\text{Foundational}, & \text{if } \text{Accuracy}_k < 0.50 \text{ or } \text{TrapFailed}_k = \text{True} \\
\text{Intermediate}, & \text{if } 0.50 \le \text{Accuracy}_k < 0.75 \\
\text{Advanced / Expert}, & \text{if } \text{Accuracy}_k \ge 0.75 \text{ and } \text{TrapFailed}_k = \text{False} 
\end{cases}
\end{equation}

\section{Mathematical Model}
\subsection{Multi-Factor Capability Score Formulation}
\begin{equation}
\text{Score}_{\text{capability}} = w_{\text{cov}} \cdot C + w_{\text{depth}} \cdot D + w_{\text{comp}} \cdot X + w_{\text{rel}} \cdot R + w_{\text{cons}} \cdot K
\end{equation}
where normalized weights default to:
$$w_{\text{cov}} = 0.20, \quad w_{\text{depth}} = 0.20, \quad w_{\text{comp}} = 0.15, \quad w_{\text{rel}} = 0.20, \quad w_{\text{cons}} = 0.15$$

\subsection{Forensic \& Composite Trust Score Formulation}
During live examination sessions, the client-side Forensic Trust Score ($S_{exam\_trust} \in [0, 100]$) quantifies candidate honesty and exam integrity:
\begin{equation}
S_{exam\_trust} = 100 - \left[ w_1 \cdot \min(N_{tab}, 10) + w_2 \cdot N_{trap} + w_3 \cdot \Delta_{conf} + w_4 \cdot G_{flag} \right]
\end{equation}
where:
\begin{itemize}
    \item $N_{tab}$ is the count of window blur and browser tab switch events ($w_1 = 2.5$).
    \item $N_{trap}$ is the number of deceptive trap questions failed ($w_2 = 18.0$).
    \item $\Delta_{conf}$ is the confidence calibration penalty for incorrect high-confidence answers ($w_3 = 5.0$).
    \item $G_{flag}$ is the binary guess detection penalty ($w_4 = 10.0$) triggered when median answer time on complex items is under 3.0 seconds.
\end{itemize}

At the global profile level, the Python Trust Calculator synthesizes all multi-engine signals:
$$\text{WeightedSum} = \sum_{m} \left( S_m \cdot W_m \right)$$
where default engine weights are:
\begin{itemize}
    \item Capability Score ($W_1 = 0.25$)
    \item Competency Score ($W_2 = 0.20$)
    \item Evidence Reliability ($W_3 = 0.15$)
    \item Repo Code Reliability ($W_4 = 0.15$)
    \item Technical Assessment ($W_5 = 0.15$)
    \item Behavioral Assessment ($W_6 = 0.10$)
\end{itemize}

Categorical fraud penalties are computed as:
$$\text{TotalPenalty} = (15.0 \times N_{\text{contradictions}}) + (5.0 \times N_{\text{missing\_sources}}) + P_{\text{fork}} + P_{\text{plagiarism}}$$
\begin{equation}
\text{FinalTrustScore} = \max\left(0.0, \, \min\left(100.0, \, \text{WeightedSum} - \text{TotalPenalty}\right)\right)
\end{equation}

\subsection{Question Quality Gate Ratios}
To prevent LLM telltale biases, distractors must satisfy strict mathematical thresholds:

\begin{equation}
R_{len} = \frac{|Len(D_j) - Len(A_{correct})|}{\max(Len(D_j), Len(A_{correct}))} \le 0.15, \quad \forall j \in \{1, 2, 3\}
\end{equation}

\begin{equation}
R_{jargon} = \frac{Count_{tech}(D_j)}{Count_{tech}(A_{correct})} \in [0.70, 1.30]
\end{equation}

const HEDGING_PATTERNS = [

const validateQualityGates = (question, options, correctIndex) => {

\chapter{Conclusion and Future Scope}

\section{Conclusion}
The traditional technical hiring pipeline has been completely broken down by the rise of generative AI tools, public repository scraping, and resume fabrication. Traditional assessment methods such as self-reported portfolio claims, static algorithmic multiple-choice tests, and passive resume parsing cannot distinguish genuine software engineering skills from memorisation or cheating via AI assistance. This project designed, deployed and empirically validated VeriProof, an enterprise-grade, evidence-driven candidate verification and skill evaluation platform to address these structural issues.

VeriProof redefines recruitment from shallow credential screening to verifiable proof-of-skill validation by integrating deep GitHub repository intelligence, automated Abstract Syntax Tree (AST) contribution analysis, Cross-Source Evidence Fusion, a 3-pass LLM bias-elimination pipeline, a two-phase computerised adaptive assessment engine, and multi-parametric forensic telemetry. The timeboxed Purgatory Intermission prevents external collaboration during adaptive test compilation while allowing the asynchronous derivation of a multidimensional Skill DNA. Experimental evaluation shows that the platform reduces assessment fatigue by up to 33\%, and provides better skill-tier differentiation than traditional 30-item fixed tests.

Moreover, the composite Forensic Trust Score can detect anomalous testing behaviours, tab switching, and LLM-assisted cheating patterns. VeriProof provides candidates with a real gamified Dynamic Skill Tree to showcase skills and provides technical recruiters with actionable fraud-resistant dossiers that reduce interview time and hiring risk significantly.

\section{Major Contributions}
The main technical and architectural contributions of the VeriProof project are:
\begin{itemize}
    \item \textbf{Two-Stage Adaptive Assessment Architecture}: Implemented a 50/50 calibration-to-scenario split. Phase 1 builds an empirical baseline for core syntax and concepts, and Phase 2 serves curated debugging puzzles and architectural trade-off scenarios synthesised to target each candidate's specific Skill DNA tier dynamically.
    \item \textbf{Strict Purgatory Intermission}: Timeboxed candidate holding state prevents external collaboration during adaptive test compilation.
    \item \textbf{3-Pass Bias Elimination Pipeline}: Algorithmic quality gates that eliminate generative AI artifacts, such as length discrepancies, hedging vocabulary patterns, and technical jargon imbalances.
    \item \textbf{Cross-Source Evidence Fusion \& Forensic Trust Synthesizer}: Reconciles resume claims against GitHub AST structures and aggregates tab-switching telemetry, trap question responses, and confidence calibration into an auditable trust metric.
    \item \textbf{Hybrid Full-Stack MERN \& FastAPI Implementation}: Production-grade reactive web application with role-based candidate and recruiter consoles bridged to an asynchronous Python analytical engine.
\end{itemize}

\section{Limitations}
\begin{itemize}
    \item \textbf{Inference Latency \& Connectivity}: Real-time AI question synthesis requires dependable internet connectivity to cloud LLM endpoints.
    \item \textbf{Repository Visibility}: Private GitHub repositories require candidate OAuth token grants for commit auditing.
