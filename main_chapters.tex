\chapter{Introduction}
\section{Background}
The current technical recruitment and academic evaluation still face the monumental challenge of fair, accurate and secure candidate evaluation. Traditional recruitment systems rely on resumes, GitHub repositories, online certifications, and portfolio websites to evaluate candidates. However, the traditional hiring platforms are vulnerable to critical attacks such as fake resumes, inflated claims of proficiency, and duplicate or purchased source-code repositories. Recruiters spend a lot of time manually cross-referencing github commit frequencies, analysing code authorship, and trying to verify whether a project is actually authored by the applicant.

Additionally, the emergence of state-of-the-art Large Language Models (LLMs) and freely accessible generative AI tools has compromised traditional online assessments. Candidates can copy questions into other browser tabs, search for solutions using generative bots, or simply memorise questions from publicly leaked question banks. While traditional Computerised Adaptive Testing (CAT) with Item Response Theory (IRT) addresses some of these issues, historically it has relied on pre-calibrated banks of tens of thousands of field-tested questions with static difficulty indices. Such approaches do not work in the fast-moving software development ecosystem where modern frameworks, languages and runtime paradigms change continuously.

VeriProof is designed, architected and built as a complete full-stack candidate proof-of-skill and anti-fraud verification ecosystem. It combines automated GitHub repo inspection, AST-level code claim auditing, a novel 3-pass LLM bias-elimination question quality pipeline, a 2-part split adaptive examination engine with strict Purgatory timeboxing, real-time client-side proctoring telemetry, and an interactive Dynamic Skill Tree. VeriProof is powered by the MERN (MongoDB, Express.js, React.js, Node.js) stack and integrated with Google Gemini 2.5 Flash and Python computer vision services, offering an auditable, transparent and meritocratic technical hiring paradigm.

\section{Problem Statement}
Existing recruitment platforms suffer from three severe, interrelated failure modes:
\begin{enumerate}
    \item \textbf{Unverifiable Portfolios \& Code Claim Fraud}: Candidates frequently claim deep full-stack or systems experience based on cloned open-source projects or template repositories without genuine code comprehension.
    \item \textbf{Vulnerability to Generative AI Assistance}: Traditional online exams rely on static, purely conceptual multiple-choice items (e.g., definitions, syntax lookups). In unsupervised environments, candidates query search engines and LLMs during testing, inflating scores without possessing practical troubleshooting competence.
    \item \textbf{Lack of Nuanced Forensic Telemetry}: Current proctoring solutions rely on crude binary disqualification triggers (e.g., webcam disconnects) rather than nuanced multi-parametric signals such as deceptive trap question responses, confidence calibration divergence, and response time distributions.
\end{enumerate}

\section{Objectives}
The core objectives of the VeriProof platform are:
\begin{enumerate}
    \item To engineer an automated pipeline that ingests unstructured Job Descriptions (JDs), parses role seniority and required skill domains, and generates balanced calibration question pools.
    \item To implement a two-stage adaptive testing architecture: Phase 1 (50\% standardized calibration) and Phase 2 (50\% dynamically personalized scenario-based debugging and architecture questions).
    \item To design a secure Purgatory Intermission system enforcing strict recruiter-configurable timeboxing (5--15 minutes) to prevent candidate collusion while asynchronously computing the candidate's multi-dimensional Skill DNA.
    \item To develop a 3-pass Question Quality Pipeline eliminating LLM biases: length disparity, hedging words, jargon imbalance, and absurd distractors.
    \item To embed proactive forensic counter-measures, including deceptive trap questions and confidence calibration prompts, to compute an aggregate Forensic Trust Score (0--100\%).
    \item To provide interactive candidate dashboards with gamified Dynamic Skill Trees and recruiter consoles with percentile rankings and forensic audit trails.
\end{enumerate}

\section{Scope of the Project}
The project scope encompasses full-stack software development, RESTful API design, database schema architecture, asynchronous worker pipelines, LLM prompt engineering with strict JSON schema enforcement, client-side event proctoring telemetry, and cloud deployment. The system enforces Role-Based Access Control (RBAC) across three distinct user personas: Candidates (Students), Recruiters (Investigators), and System Administrators.

\section{Methodology}
The platform adopts a decoupled multi-tier client-server architecture:
\begin{itemize}
    \item \textbf{Presentation Tier}: Single-page application built on React 18, Vite, Tailwind CSS, Lucide-React, and Framer Motion, delivering responsive portals for candidate assessment, portfolio management, and recruiter candidate discovery.
    \item \textbf{Application \& API Tier}: Node.js and Express.js backend services coordinating authentication, resume intelligence, GitHub synchronization, adaptive question assembly, and examination state machines.

    \item \textbf{Data Tier}: MongoDB Atlas clustered NoSQL datastore managing document schemas for users, parsed resume claims, repositories, dynamic skill progression nodes, and examination audit logs.
\end{itemize}

\section{Review of Existing Work}
Marinin et al. [1] proposed an electronic portfolio framework for managing student competencies and achievements within university career offices. Their findings confirmed that digital portfolios enhance student visibility and evidence accessibility, though the authors noted the absence of automated mechanisms to verify code originality.

Vaishampayan et al. [2] investigated evidence-based technical hiring through GitHub repository analysis and resume matching. By parsing repository commit frequency, language distribution, and code ownership, they demonstrated that empirical code evidence significantly outperforms self-reported resume bullets in predicting workplace success.

Mujtaba and Mahapatra [3] analyzed algorithmic fairness, transparency, and bias mitigation in AI-driven recruitment platforms. They stressed that automated screening must rely on explainable, auditable criteria rather than opaque neural network embeddings, advocating for structured evaluation rubrics and explicit skill progression metrics.

Akram et al. [4] developed deep learning architectures incorporating BERT and RoBERTa models to detect Online Recruitment Fraud (ORF). Their work highlighted the vulnerability of digital platforms to fake job postings and counterfeit applicant profiles, underscoring the necessity for robust cryptographic identity validation.

Lebopa et al. [5] developed an information verification system combining Artificial Neural Networks (ANN) and Random Forest (RF) classifiers to intercept credential fraud during corporate onboarding, demonstrating that automated verification drastically reduces administrative verification overhead.

Thandar et al. [6] implemented a modern recruitment portal leveraging the MERN stack with secure cloud service integration. Their architecture verified that combining React, Node.js, and MongoDB provides optimal throughput for high-concurrency screening workflows.

Dugyala et al. [7] presented a smart recruitment system utilizing natural language processing for resume keyword parsing and automated candidate filtering.

Adawiah and Putra [8] examined candidate trust and employer credibility in e-recruitment environments. Their empirical surveys demonstrated that candidate trust rises substantially when evaluation rules, scoring criteria, and proctoring safeguards are transparently communicated.

Agazzi [9] performed usability investigations into digital recruitment interfaces, proving that cognitive fatigue among hiring managers is strongly correlated with poorly organized, unverified candidate profiles.

Ajayi and Udeh [10] reviewed modern IT recruitment strategies, demonstrating that practical problem-solving assessments, debugging scenarios, and gamified skill trees provide far higher predictive validity than unstructured whiteboard interviews.

Wainer et al. [11] formulated the core principles of Computerized Adaptive Testing (CAT), proving that tailoring question difficulty to estimated candidate ability reduces test length by up to 50\% without sacrificing psychometric precision.

Vaswani et al. [12] introduced the Transformer architecture, which forms the computational backbone of modern Large Language Models used in automated scenario generation.

\section{Existing System}
The prevailing recruitment process relies on manual inspection of submitted PDF resumes, self-reported skills on professional networking portals, and static multiple-choice examinations. Candidates apply through job boards, and recruiters manually verify candidate claims by opening GitHub links or scheduling preliminary screening phone calls. Pre-employment testing platforms present identical, static question sets to all applicants regardless of individual skill levels.

\section{Limitations of Existing System}
\begin{enumerate}
    \item \textbf{Susceptibility to Code Fraud}: Candidates easily fork popular open-source repositories or purchase turnkey projects, claiming primary authorship without possessing basic architectural understanding.
    \item \textbf{Question Leaking \& Cheating via Generative AI}: Fixed test banks leak online. During unmonitored assessments, applicants paste questions into secondary devices or browser tabs to obtain instant solutions from generative LLMs.
    \item \textbf{Recruiter Operational Inefficiency}: Recruiters expend hundreds of hours sifting through inflated resumes and conducting introductory screening calls for unqualified applicants.
    \item \textbf{Binary Pass/Fail Measurement}: Conventional systems score candidates on an elementary percentage scale that fails to capture domain-specific strengths, weaknesses, or behavioral authenticity.
\end{enumerate}

\section{Proposed System}
VeriProof replaces unverified assertions with cryptographic proof-of-skill. The proposed platform:
\begin{itemize}

    \item Executes a 2-part adaptive examination: Phase 1 establishes an empirical baseline across core competencies, followed by a timeboxed Purgatory Intermission, culminating in Phase 2 practical scenario debugging.
    \item Synthesizes an aggregate Forensic Trust Score based on proctoring telemetry, trap question responses, and confidence calibration.
    \item Renders an interactive Dynamic Skill Tree illustrating candidate mastery milestones.
\end{itemize}

A 3-pass generative AI engine that prevents common LLM artifacts:

    \item \textbf{Pass 3}: Code-based quality gates verifying distractor plausibility and randomizing answer positions (A, B, C, D).

Orchestrates the 2-part split architecture:

\section{Proposed Methodology / Algorithm}
The candidate Skill DNA classification algorithm computes empirical proficiency vectors across all evaluated technical domains:

\begin{equation}
Accuracy\_k = \frac{\sum_{i=1}^{N_k} C_{k,i}}{N_k} , \quad C_{k,i} \in \{0, 1\}
\end{equation}

\begin{equation}
\bar{T}\_k = \frac{1}{N_k} \sum_{i=1}^{N_k} T_{k,i}
\end{equation}

where $C_{k,i}$ is the correctness of question $i$ in skill domain $k$, $T_{k,i}$ is response duration in milliseconds, and $N_k$ is total questions in domain $k$.

The candidate is assigned to a competency tier per domain:

\begin{equation}
Tier\_k = \begin{cases} 
Foundational, & \text{if } Accuracy\_k < 0.50 \text{ or } TrapFailed\_k = \text{True} \\
Intermediate, & \text{if } 0.50 \le Accuracy\_k < 0.75 \\
Advanced / Expert, & \text{if } Accuracy\_k \ge 0.75 \text{ and } TrapFailed\_k = \text{False} 
\end{cases}
\end{equation}

\section{Mathematical Model}
\subsection{Forensic Trust Score Formulation}
The composite Forensic Trust Score ($S_{trust} \in [0, 100]$) quantifies candidate honesty and exam integrity:

\begin{equation}
S_{trust} = 100 - [ w_1 \cdot \min(N_{tab}, 10) + w_2 \cdot N_{trap} + w_3 \cdot \Delta_{conf} + w_4 \cdot G_{flag} ]
\end{equation}

where:
\begin{itemize}
    \item $N_{tab}$ is the count of window blur and browser tab switch events ($w_1 = 2.5$).
    \item $N_{trap}$ is the number of deceptive trap questions failed ($w_2 = 18.0$).
    \item $\Delta_{conf}$ is the confidence calibration penalty for incorrect high-confidence answers ($w_3 = 5.0$).
    \item $G_{flag}$ is the binary guess detection penalty ($w_4 = 10.0$) triggered when median answer time on complex items is under 3.0 seconds.
\end{itemize}

\subsection{Question Quality Gate Ratios}
To prevent LLM telltale biases, distractors must satisfy strict mathematical thresholds:

\begin{equation}
R_{len} = \frac{|Len(D_j) - Len(A_{correct})|}{\max(Len(D_j), Len(A_{correct}))} \le 0.15, \quad \forall j \in \{1, 2, 3\}
\end{equation}

\begin{equation}
R_{jargon} = \frac{Count_{tech}(D_j)}{Count_{tech}(A_{correct})} \in [0.70, 1.30]
\end{equation}

\section{Two-Phase Adaptive Assessment \& Purgatory Timebox}
The Purgatory Intermission mechanism boxes the candidate between Part 1 and Part 2:
\begin{itemize}
    \item The client displays a prominent countdown timer (default 10 minutes, configurable from 5 to 15 minutes).
    \item Part 2 contains zero conceptual questions, neutralizing the temptation to search Google during the break.
    \item If the timer expires before the candidate clicks ``Start Part 2'', the exam finalizes automatically using only Part 1 scores, applying a severe abandonment penalty.
\end{itemize}

// Code snippet from backend/services/questionQualityPipeline.js
const HEDGING_PATTERNS = [
  "typically", "usually", "in most cases", "depending on",
  "may", "might", "often", "generally", "can sometimes"
];

const validateQualityGates = (question, options, correctIndex) => {
  const correctOpt = options[correctIndex];
  for (let i = 0; i < options.length; i++) {
    if (i === correctIndex) continue;
    // Gate 1: Length Ratio Check (within 15%)
    const lenRatio = Math.abs(options[i].length - correctOpt.length) /
      Math.max(options[i].length, correctOpt.length);
    if (lenRatio > 0.15) {
      return { passed: false, reason: "LENGTH_BIAS" };
    }
    // Gate 2: Absurd distractor rejection
    if (ABSURD_PATTERNS.some(pat => pat.test(options[i]))) {
      return { passed: false, reason: "ABSURD_DISTRACTOR" };
    }
  }
  return { passed: true };
};
\end{lstlisting}

\chapter{Conclusion and Future Scope}
\section{Conclusion}
The VeriProof platform delivers an enterprise-grade, evidence-based solution for technical recruitment. By uniting automated GitHub repository inspection, a 3-pass LLM bias-elimination pipeline, a 2-part adaptive assessment architecture with Purgatory timeboxing, and multi-parametric forensic trust scoring, the system overcomes the profound limitations of static resume screening and multiple-choice testing. Candidates showcase verified, authentic engineering talent through an interactive Dynamic Skill Tree, while recruiters gain actionable, fraud-resistant candidate dossiers.

\section{Major Contributions}
\begin{itemize}
    \item \textbf{Two-Stage Adaptive Architecture}: A 50/50 calibration-to-scenario split that personalizes question difficulty based on empirical Skill DNA.
    \item \textbf{Strict Purgatory Intermission}: Timeboxed candidate holding state preventing external collaboration during adaptive test compilation.
    \item \textbf{3-Pass Bias Elimination Pipeline}: Automated quality gates eliminating LLM length biases, hedging tells, and absurd options.
    \item \textbf{Multi-Factor Forensic Trust Synthesizer}: Combines tab-switching telemetry, trap question responses, and confidence calibration into an auditable trust metric.
    \item \textbf{Full-Stack MERN Implementation}: Production-grade reactive web application with role-based candidate and recruiter consoles.
\end{itemize}

\section{Limitations}
\begin{itemize}
    \item Real-time AI question synthesis requires dependable internet connectivity to cloud LLM endpoints.
    \item Private GitHub repositories require candidate OAuth token grants for commit auditing.
\end{itemize}

\section{Future Scope}
\begin{itemize}
    \item \textbf{In-Browser WebAssembly Sandboxes}: Providing sandboxed live code execution environments for automated unit test execution.
    \item \textbf{Lightweight WebGL Gaze Tracking}: On-device eye-tracking proctoring that preserves candidate privacy without external video streaming.
    \item \textbf{Decentralized Credential Verification}: Anchoring completed Skill Tree milestones onto public cryptographic ledgers for tamper-proof portfolio sharing.
\end{itemize}
